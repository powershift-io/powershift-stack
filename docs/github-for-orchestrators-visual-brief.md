# GitHub for Orchestrators: Infographic and Video Brief

**Status:** production brief draft
**Audience:** Public Stack Steward, designers, video producers, Remotion/Hyperframes builders, and Orchestrators shaping public teaching assets.
**Purpose:** define the visual layer that can support both [GitHub Without the Git](github-without-the-git.md) and [GitHub for Orchestrators](github-for-orchestrators.md).

## Core visual thesis

GitHub is a shared, versioned workbench for humans and Minds.

For PowerShift, it functions as:

- public shelf;
- sync bridge;
- governance record;
- backup and rollback layer;
- collaboration surface;
- Mind Conduit substrate;
- app-store-like shelf for reusable intelligence infrastructure.

The visual system should make GitHub feel ordinary enough to approach and powerful enough to respect.

## Ownership and home

### Source-of-truth content

**Owner:** Public Stack Steward
**Home:** the PowerShift Stack repo

The Markdown docs belong natively in the repo. They are public-stack source material: readable, forkable, reviewable, and useful to humans and Minds before any design treatment exists.

The Steward owns:

- Markdown source docs;
- README navigation;
- public-safe examples and diagrams committed to the repo;
- issue and pull-request routing for content improvements;
- release notes when these docs become part of a named Stack release.

### Designed publication assets

**Owner:** PowerShift Ecosystem Asset Steward, provisional pending governance processing
**Home:** shared asset library plus published distribution surfaces

The polished PDF, infographic, slide-friendly versions, and video assets are ecosystem publication assets. They use the Stack docs as source material, but they are not themselves the canonical source of the educational content.

This work needs a cross-asset production owner because it touches:

- PowerShift visual identity;
- reusable illustration language;
- PDF and presentation styling;
- video production patterns;
- brand cohesion across PowerShift-affiliated surfaces;
- distribution beyond the repo.

### Practical routing

1. Public Stack Steward keeps the Markdown clean and current.
2. Ecosystem Asset Steward turns approved source content into designed assets.
3. Public Stack repo links to the designed assets once published.
4. The designed assets link back to the source docs for provenance and revision history.

### Recommended artifact homes

| Artifact | Primary home | Notes |
|---|---|---|
| Markdown source | `powershift-stack/docs/` | Canonical text and review history |
| Diagram source | `powershift-stack/docs/diagrams/` or asset-library source folder | Commit source files where useful |
| Lightweight infographic export | repo plus published page | Good candidate for public README/docs linking |
| Polished PDF | public website / here.now / release asset | Repo can link to it; source stays in Markdown/design files |
| Short explainer video | video channel plus public page | Repo links out; production files live with media pipeline |
| Remotion/Hyperframes project | separate production folder or repo if it becomes reusable | Keep if it becomes a repeatable video system |

## Video seed: 90-second explainer

### Working title

**GitHub Without the Git**

### Target viewer

A capable founder, operator, or community member who has heard "repo" enough times to suspect there is power behind the fog.

### Beat outline

1. **0:00-0:10 - Hook**
   - "GitHub is usually explained as a developer tool. For Orchestrators, the simpler idea is this: it is a shared folder with memory."

2. **0:10-0:25 - The five questions**
   - Show current version, what changed, who changed it, why, and whether it can be reviewed or restored.

3. **0:25-0:40 - App store for intelligence**
   - Show PowerShift Stack artifacts as reusable building blocks.
   - Mention human-readable plus machine-readable.

4. **0:40-0:58 - The repo is the room**
   - Show humans and Minds working around the same visible artifact.
   - GitHub holds the table, the history, and the review path.

5. **0:58-1:15 - PowerShift use cases**
   - Stack repo, sync bridge, governance record, backup/rollback, Mind Conduits.

6. **1:15-1:30 - Invitation**
   - "Start by reading the README, opening one issue, and looking at one change. That is enough to begin."

### Visual tone

- Clean, warm, diagrammatic.
- Light humor in labels, not slapstick.
- Avoid dense code screens.
- Show GitHub UI only where useful: README, Issues, Pull Requests, Files changed.
- Use PowerShift visual language after the Markdown drafts settle.

## Video seed: 3-5 minute explainer

### Working title

**The Repo Is the Room**

### Structure

1. GitHub in one sentence.
2. Why normal folders break down.
3. What a repo remembers.
4. How governance shows up as change history.
5. How PowerShift uses GitHub today.
6. Why Minds can read repos so effectively.
7. What nontechnical Orchestrators should learn first.
8. What belongs in public and what stays private.

### Candidate production formats

- **Remotion:** good for code-driven motion graphics, versionable alongside the Stack, and reusable templates.
- **Hyperframes:** good candidate for fast explainer construction if the workflow is already smooth in the PSI environment.
- **Static-first path:** infographic first, then animate the same visual system later.

The static-first path is probably the cleanest first move. It lets the message stabilize before production mechanics start eating the schedule.
